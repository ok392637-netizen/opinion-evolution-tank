# 观点进化缸 · Opinion Evolution Tank

### 产品说明计划书 ｜ 知乎黑客松 2026 · 校园新锐季

**赛道：📚 知识炼金场（社区 × 学习）**
**活动代码：** `zhihu_hackathon_2026_p2`

> **一句话**：把每一个知乎问题变成一个可观察、可干预、可放生的「观点生态系统」——
> 不是帮你读知乎，而是让你**像生物学家一样围观知乎**。

---

## 一、核心创作思路

### 1.1 我们发现的问题

知乎表面上是一个问答社区，实质上是一个**观点的自然选择场**。

一个问题下几十上百个回答，在争夺同一种稀缺资源：注意力。
赞同是能量，评论是繁殖，权威是体型，热榜是气候突变。
最后留在顶部的高赞回答，**不一定是最正确的那个，而是最适应当时生态位的那个物种**。

但今天的知乎只把「结果」呈现给你——高赞排在最上面。你看不见的是：

- 为什么是**这一条**活下来了？它靠的是数据、故事、情绪，还是身份认同？
- 同一个观点，换一个问题、换一个时间点，还能不能活？
- 我现在写的这条回答，扔进去会怎样？

这对两类人是真实的痛点：

| 人群 | 痛点 | 现状 |
|---|---|---|
| **创作型知友** | 花两小时写完一条回答，发出去石沉大海，**事后也不知道为什么** | 只能凭感觉试错，一次试错成本 = 一次真实发布 |
| **围观型知友 / 内容研究者** | 想看懂一个争议话题的观点结构，但只能一条条往下刷 | 高赞遮蔽长尾，看到的是排序结果，不是观点地图 |

### 1.2 我们的解法

**把「看不见的观点竞争」变成一个可以观察、可以调参、可以做实验的生态缸。**

- **观察**：一个问题 = 一缸。每条回答 = 一个物种，标注它的**立场**（支持/反对/中立/解构/反讽/补充）与**生存策略**（数据论证/情绪共鸣/故事叙事/身份站队/抖机灵/引用权威）。圆面积 = 能量（赞同数），描边粗细 = 权威等级，圆内符号 = 生存策略。
- **干预**：改变缸的规则——推荐算法偏高赞还是偏新答？气候偏理性还是偏情绪？大 V 加权还是匿名平权？**同一个问题，在不同的平台规则下，胜出的观点物种完全不同。**
- **放生**：写一段你自己的回答，扔进缸里，看它在**当前生态**中的存活预测、会被谁压制、可以怎么「杂交」提高存活率。**这是一次零成本的发布预演。**

### 1.3 我们和已有产品的根本差异

| 维度 | 已有产品（摘要 / 推荐 / 舆情分析） | 观点进化缸 |
|---|---|---|
| 核心对象 | 内容本身 | 观点之间的**生态关系** |
| 时间维度 | 静态快照 | **入场演化 + 参数化推演** |
| 用户角色 | 读者、消费者 | **生态学家、干预者、放生者** |
| AI 的作用 | 总结、推荐 | **结构化、模拟、预测** |
| 回答的问题 | 「我该看什么？」 | 「**观点为什么活下来？**」 |

它不是推荐系统，不是舆情分析，不是 AI 辩论。
它是**观点生态的显微镜 + 模拟器 + 实验缸**。

## 二、目标用户与核心体验路径

### 2.1 目标用户

| 用户 | 使用场景 | 得到什么 |
|---|---|---|
| 创作型知友 | 发回答前先「放生」试水 | 存活预测 + 具体到句子的改写建议 |
| 围观型知友 | 围观热榜争议问题 | 一眼看懂「这个问题下正在打什么仗」 |
| 内容研究者 / 运营 | 横向对比不同问题 | 哪种叙事策略在哪种生态位有效 |

### 2.2 评委 3 分钟体验路径

```
① 打开首页 → 热榜选题台（知乎热榜实时数据）
        ↓  点任意一条（标「缸已就绪」的秒开）
② 生态缸生成 → 官方接口直取该问题下的真实回答，逐条标注物种与策略
        ↓
③ 拖动「演化时间轴」→ 回答按发布时间依次入场，看生态如何长成现在这样
        ↓
④ 切换「环境干预」四个参数 → 生态图实时重算，优势物种当场易主
        ↓
⑤ 「放生实验」写一段自己的回答 → 存活概率 + 压制来源 + 杂交建议
        ↓
⑥ 「生态报告」一键导出观点进化图谱长图 → 可直接发回知乎形成二次讨论
```

**全程无需登录、无需配置，打开即用。**

## 三、整体技术方案

### 3.1 架构

```
┌──────────── 前端 React 18 + TypeScript + Vite ────────────┐
│  热榜选题台 │ 生态缸 SVG │ 演化时间轴 │ 环境干预 │ 放生 │ 报告导出 │
│  力导向布局 d3-force（同步 300 tick）· 报告自绘 SVG → PNG       │
└──────────────────────────┬────────────────────────────────┘
                           │ HTTPS，只传 JSON，前端零凭证
┌──────────────────────────▼────────────────────────────────┐
│  后端 Node + Express（Access Secret 唯一持有方）              │
│  ┌─ 数据层：双通道抓取 + LCS 交叉富化                          │
│  ┌─ 智能层：本地可解释标注器（零额度）× 知乎直答生态解说         │
│  ┌─ 模拟层：透明规则概率模型（公式公开）                        │
│  └─ 治理层：五道额度闸（缓存/去重/持久化/守卫/降级）             │
└──────┬──────────────┬──────────────┬──────────────────────┘
       ▼              ▼              ▼
   知乎热榜        知乎搜索       知乎问题回答 / 知乎直答
```

### 3.2 数据层：双通道抓取 + 交叉富化

官方文档中**没有**「问题 ID → 回答列表」接口。我们在实测额度清单时发现了一个**文档未记载的端点**
`GET /api/v1/content/question_answers`（传完整问题 URL，返回该问题下的真实回答与分页游标），
使「按问题抓回答」这一核心诉求成立。由此形成双通道：

- **通道 A（首选）**：问题 URL → `question_answers` 直取回答列表。
  该端点不返回赞同数，因此再用 `zhihu_search` 搜同题结果，
  以**最长公共子串 ≥ 20 个连续汉字**判定为同一条回答，把赞同数/评论数/作者/权威等级富化进去。
  > 为什么是 LCS 而不是前缀匹配：搜索摘要是**围绕查询词偏置的中段片段**，
  > 与回答开头往往对不上——前缀匹配实测命中率为 0。
  富化失败的条目**如实标注为「按热序近似」，绝不编造赞同数**。
- **通道 B（兜底）**：只有问题标题时，用 `zhihu_search` 汇聚相关回答，按 2-gram 重现率做相关性过滤。

### 3.3 智能层：双通道标注 —— 这是本项目最重要的一次工程取舍

**我们踩到的坑：** 最初的设计是把知乎直答当作「输出 JSON 的分类器」，
给它 system prompt 要求严格输出 `[{stance, strategy, summary}]`。

**实测结果：直答完全忽略格式指令。** 它是一个**问答 / 检索产品**，
会从输入里认出那个知乎问题，然后返回一篇带检索来源的知乎风格长回答。
（原始响应留证在 `docs/evidence/zhida-raw-2026-09-13.json`。）
后果是标注全部落进降级分支，**40 个物种被清一色标成「中立 · 数据论证」**——
可视化变成一坨同色圆点，产品的核心概念根本没被呈现出来。

**我们的重构：不再逼一个问答模型做它不擅长的事，而是按能力分工。**

| 通道 | 做什么 | 用什么 | 额度消耗 |
|---|---|---|---|
| **A. 逐条标注** | 每条回答的立场 × 生存策略 | **本地可解释标注器**（中文词典 + 句法规则 + 问题类型先验） | **0** |
| **B. 生态解说** | 整缸一段「这个问题下有哪几派、各靠什么立住」 | **知乎直答** `zhida-thinking-1p5`，自然语言提问 | 1 次/缸，随缸永久缓存 |
| **C. 放生点评** | 这条草稿会遭到哪些反驳 | 知乎直答，自然语言提问 | 1 次/次，可降级 |

这个取舍带来三个好处，而不只是「绕过一个 bug」：

1. **可解释性从缺点变成卖点。** 每一个标注都可以展开，看到**是哪些词触发了这个判断**
   （例：判为「反讽」是因为同时命中了「学会了」「支个招」「遥遥领先」三个反语特征）。
   一个能被追问「你凭什么这么判」的模型，在知识产品里比一个黑箱 LLM 更有说服力。
2. **两条独立路径互相印证。** 直答说「这个问题下有 4 派」，本地标注器逐条统计也得到 4 类——
   两个完全不同的方法得到一致结论，这比单一来源的断言可信。
3. **主流程零 AI 依赖，评委随便点都不会挂。** 见 3.5。

标注器还内置**分布健康检查**：如果 ≥80% 的物种落进同一类，说明特征失效，
系统会主动挂出「标注可信度低」的告警，而不是假装成功——
这条规则正是从上面那次「静默全灰」的失败里长出来的。

### 3.4 模拟层：透明的存活概率模型

放生实验的存活概率**不是让模型随口给一个数**，而是一个公开可复算的公式：

```
P = 100 × ( 0.35 × 策略蓝海度      // 1 − 同策略物种占比
          + 0.25 × 立场差异化      // 1 − 同立场物种占比
          + 0.20 × 权威压力缓冲    // 缸内最高权威等级带来的压制
          + 0.20 × 互动基础度 )    // 缸内评论热度的边际收益
```

公式直接展示在界面上。**用户可以不同意这个模型，但可以看懂它。**

### 3.5 治理层：五道额度闸（这一层决定了 Demo 当天活不活）

校园季试用额度**远小于公开文档标称值**，实测：

| 能力 | 文档 | 实测日额度 |
|---|---:|---:|
| 知乎直答 | 100 | **2** |
| 知乎热榜 | 100 | **2** |
| 知乎搜索 | 5000 | **10** |
| 问题回答 | 未记载 | **10** |

在这个约束下，任何「每次交互都实时调 API」的设计都会在评审当天当场失败。我们做了五道闸：

1. **结果缓存**：热榜 12h / 生态缸 24h / 搜索 6h / 问题回答 6h / 放生 1h
2. **并发去重**：同 key 并发只发一次上游调用（防双击、防前端重试双倍消耗）
3. **磁盘持久化**：生态缸缓存落盘，服务重启不丢「已经用额度换来的数据」
4. **直答双层守卫**：本地日计数 + 服务端余量确认（额度查询本身免费）
5. **降级链**：热榜耗尽 → 演示热榜 + 显式警告横幅；直答不可用 → 纯规则模型；
   搜索失败 → 热序近似。**每一级降级都在界面上如实说明，不用假数据冒充实时。**

外加**演示缸预构建**：提前把若干热榜问题的生态缸构建好并随仓库提交，
评委点这些问题**零额度、秒开**。

## 四、使用的知乎开放能力

| 能力 | 接口 | 在产品中的位置 |
|---|---|---|
| 知乎热榜 | `GET /api/v1/content/hot_list` | 首页选题台，实时热榜 Top 30 |
| 知乎问题回答 | `GET /api/v1/content/question_answers` | **通道 A**：按问题直取真实回答列表 |
| 知乎搜索 | `GET /api/v1/content/zhihu_search` | 通道 A 的赞同数富化 / 通道 B 的样本汇聚 |
| 知乎直答 | `POST /v1/chat/completions`（`zhida-thinking-1p5`） | AI 生态解说 · 放生点评 |
| 额度查询 | `GET /api/v1/quota` | 服务端守卫与前端余量展示（本身不消耗额度） |

鉴权统一 `Authorization: Bearer <Access Secret>` + `X-Request-Timestamp`（秒级）。
**Access Secret 只存在于服务端环境变量**，不进前端代码、URL、日志、截图与代码仓库。

## 五、与知乎社区生态的契合点

1. **对象就是知乎本身。** 这个产品不是「一个恰好用了知乎数据的工具」——
   它的分析对象是知乎的问答生态结构，换任何一个平台都不成立。
2. **产出回流社区。** 「观点进化图谱」长图带原问题链接与数据来源水印，
   设计初衷就是**发回那个问题下形成二次讨论**——产品的输出本身就是社区内容。
3. **对创作生态是正向的。** 放生实验给的是**表达建议**（「加一段个人故事」「补一个可验证的数据源」），
   引导用户把回答写得更扎实，而不是更会蹭。
4. **只读、不打扰。** 全程无写操作、无批量抓取、无自动发布。
   五道缓存闸的存在本身就是对开放平台使用规范的遵守。
5. **直答用在它擅长的地方。** 我们用直答做「这个问题下有哪几派观点」这类
   **需要检索与归纳的开放式问答**，而不是把它当廉价分类器——这也是对社区官方 AI 能力的正确使用姿势。

## 七、诚信声明（我们主动写在产品里的边界）

做这个产品最容易越界的地方，是拿推演当史实。我们把边界写死在界面上：

- **演化时间轴**顶部固定徽标「**AI 演化重建 · 非历史记录**」。
  官方 API 只提供当前时点数据，时间轴是按回答发布/编辑时间重演入场过程，
  **不代表真实的历史赞同曲线**。
- **放生实验**报告角标「**AI 模拟预测**」，不代表知乎平台真实数据。
- **标注置信度**：本地标注器给出的置信度低于阈值时，界面显示「低置信」角标，
  **不把不确定伪装成确定**。
- **降级如实告知**：额度耗尽、搜索无结果、赞同数无法匹配，界面都显式说明当前处于哪种降级状态。
- **演示模式**使用虚构作者名并有醒目徽标，**绝不冒充真实知乎用户内容**。
- 原方案中的「折叠回答化石层」「作者粉丝数」「收藏数」三项，
  因官方 API 确实不提供而**主动移除**，不做无法溯源的声称。
