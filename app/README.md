# 观点进化缸 · Opinion Evolution Tank

> **把每一个知乎问题变成一个可观察、可干预、可放生的"观点生态系统"——像生物学家一样围观知乎。**
>
> 不是帮你读知乎，而是让你亲眼看到观点如何竞争、变异、杂交、上岸。

知乎黑客松 2026 · 校园新锐季参赛作品（建议赛道：知识炼金场）。全部数据来自知乎开放平台官方 API，AI 能力使用知乎直答。

## 核心体验（评委 3 分钟路径）

1. **热榜选题台** → 从实时热榜选一个问题（或输入任意问题标题）
2. **生态快照** → 官方搜索接口汇聚回答样本，直答 AI 批量标注"观点物种 × 生存策略"
3. **生态缸** → 力导向图实时渲染：圆面积 = 环境能量（赞同数），颜色 = 立场，虚线 = 对立阵营竞争
4. **演化时间轴** → 拖动滑杆看观点按发布时间依次入场（标注：AI 演化重建 · 非历史记录）
5. **环境干预** → 切换推荐权重 / 情绪气候 / 大 V 加权，生态图实时重算（本地可解释模型，零 API 消耗）
6. **放生实验** → 写一段自己的回答"放生"进缸，获得生存概率 + 压制来源 + 杂交建议（AI 模拟预测）
7. **生态报告** → 一键导出可分享回知乎的观点进化图谱长图

## 快速开始

```bash
# 1. 服务端（端口 8787）
cd server
npm install
cp .env.example .env   # 填入 ZHIHU_ACCESS_SECRET（见下）
npm run dev

# 2. 前端（端口 5173，开发模式代理 /api）
cd ../web
npm install
npm run dev
```

浏览器打开 <http://localhost:5173>。

**生产模式**（单服务托管）：`cd web && npm run build`，然后 `cd ../server && npm start`——Express 会自动托管 `web/dist`，访问 <http://localhost:8787> 即可。

### 数据模式

| 模式 | 触发条件 | 行为 |
|---|---|---|
| **实时模式** | 配置 `ZHIHU_ACCESS_SECRET` | 双通道真实数据（见下），可溯源 |
| **演示模式** | 未配置 | 内置演示数据集驱动全部交互，前端顶部有醒目"演示数据"徽标 |

获取 Access Secret：登录 <https://developer.zhihu.com/profile> → 申请新 Access Secret → 填入 `server/.env`。**凭证只存服务端，绝不出现在前端代码、日志与截图中。**

### 双通道数据管线（核心设计）

```
通道 A（首选）：问题 URL ──→ question_answers 直取该问题下回答列表（10 条/页）
                     │
                     └─ LCS≥20 字符匹配 ←── 知乎搜索（同题）──→ 富化赞同数/评论数/作者/权威等级
                             （20+ 连续相同汉字才判定同一回答，未匹配的按热序近似并如实标注）

通道 B（兜底）：仅问题标题 ──→ 知乎搜索汇聚相关回答样本（2-gram 相关性过滤）
```

> `question_answers` 为 2026-09-13 实测发现的隐藏端点（不在官方文档中），使原方案"按问题抓取回答"成为可能。

### 每日额度与缓存策略（以实测为准，校园季试用额度远小于公开文档值）

| 能力 | 实测日额度 | 本项目策略 |
|---|---|---|
| 知乎问题回答 | 10 | 生态缸结果缓存 24 小时；通道 A 每缸 1 次 |
| 知乎搜索 | 10 | 富化/兜底每缸 1 次 |
| 知乎热榜 | 2 | 服务端缓存 12 小时；耗尽时降级演示热榜并醒目告知 |
| 知乎直答 | 2 | 守卫阈值可配（`ZHIDA_DAILY_LIMIT`）；标注每缸 1 次、失败自动降级规则模型；放生分析余量不足时自动切纯规则模式 |
| 额度查询 | 免费 | `/api/quota` 透传，`/api/v1/quota` 调用本身不消耗业务额度 |

**演示日预案**：额度每日 0 点重置。建议上午先构建 1-2 个演示问题的生态缸（缓存 24h），将直答留给现场放生演示。

### 额度防泄漏设计（五道闸）

1. **结果缓存**：热榜 12h / 生态缸 24h / 搜索 6h / 问题回答 6h / 放生分析 1h（问题+草稿哈希）
2. **并发去重**：同 key 并发请求只发一次上游调用（防双击、防前端重试双倍消耗）
3. **磁盘持久化**：生态缸缓存落盘 `server/data/`，服务重启不丢已消耗额度换来的数据
4. **直答双层守卫**：本地日计数 + 服务端余量确认（quota 查询免费，缓存 60s）
5. **降级链**：热榜空列表→演示热榜+警告横幅；直答不可用→纯规则模型；搜索失败→热序近似，全部如实标注

## 技术架构

```
web (React 18 + TS + Vite + d3-force)  ←→  server (Node + Express)  ←→  知乎开放平台
     生态缸 SVG / 时间轴 / 干预 / 报告         缓存 · 额度守卫 · 凭证          热榜/搜索/直答
```

- **前端**：React 18 + TypeScript + Vite；力导向布局用 d3-force（同步 300 tick，无动画抖动）；报告导出为自绘 SVG → PNG，无外部资源、无 canvas 污染。
- **后端**：Express，仅 1 个运行时依赖；内存缓存 + 请求去重；直答调用计数守卫。
- **AI**：`zhida-fast-1p5` 批量物种标注（1 次调用标注全部样本），`zhida-thinking-1p5` 放生深度分析；强制 JSON 输出 + 健壮解析，失败自动降级为规则模型，**绝不编造数据**。
- **存活概率**：AI 预测与透明规则模型按 6:4 混合。规则公式：
  `P = 100 × (0.35×策略蓝海度 + 0.25×立场差异化 + 0.20×权威压力缓冲 + 0.20×互动基础度)`

## 诚信声明（评审重点）

- 演化时间轴基于回答发布/编辑时间**重建推演**，界面与报告均标注"AI 演化重建 · 非历史记录"；
- 放生结果为"AI 模拟预测"，不代表知乎平台真实数据；
- 演示模式的示例内容使用虚构作者名，绝不冒充真实知乎用户；
- 搜索相关性不足时如实展示"未标注"，不编造分类结果。
